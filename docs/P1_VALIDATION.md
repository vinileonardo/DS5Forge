## Independent P1 review fixes

The independent review reproduced the implementation gates and corrected the
following issues before technical GO:

- HTTP CORS is no longer treated as sufficient CSRF protection for the loopback
  API: browser requests carrying an unapproved `Origin` now receive structured
  `403 api.origin_rejected` before state-changing handlers can reach the core;
- a WebSocket transport is not marked `online` until the mandatory initial
  `state.snapshot` validates, preventing stale controller state from briefly
  becoming trusted during reconnect;
- the Haptics live toggle now has an explicit pending lock, preventing duplicate
  mutations while the core command is in flight;
- the destructive profile confirmation dialog now traps keyboard focus, closes
  with Escape when safe, and restores focus to the invoking control;
- `tauri:build` now owns its frontend production build through
  `beforeBuildCommand`, and development has a separate narrow `devCsp` that
  explicitly permits only the local Vite HMR WebSocket in addition to the core;
- the Windows resource build now has a deterministic P1 placeholder icon
  generated by `build.rs` only when no real `icons/icon.ico` exists. It adds no
  runtime dependency and is intentionally replaced by final product branding in
  P4 rather than blocking P1 native compilation.

The post-review automated suite remains green with 48 Python tests, 13 Vitest
tests and 3 Playwright tests.

## Known limitations

- No Windows + real DualSense USB run was available in this environment.
- `customtkinter` remains intentionally available as the documented fallback;
  the browser/Tauri SPA is the P1 primary path.
- The P1 Playwright flows use deterministic browser fixtures for HTTP/WS
  bootstrap, mutation and reconnect. Authenticated hardware persistence and
  physical USB behavior remain outside this host's evidence.
